# Harness tune — prompt template

The weekly self-improvement pass: the backpass idea implemented natively. Worker transcripts plus a metrics ledger are the loss signal, this pass is the gradient step, the human is the gate. This template IS the live prompt: `bin/render_prompts.py` substitutes the deployment config's `{{tokens}}` and `bin/install_crons.py` installs the rendered body into the scheduler — edit here (or in the config), never in the scheduler directly. It also triages the public repo's new issues and publishes the repo through a fail-closed gate.

Fewer than 4 runs this week → light pass, say the sample is thin.
2. For the top 2-3 failure classes, pull the relevant transcript excerpts: grep the transcript files for abort/error lines and read the surrounding steps. Read excerpts, never whole files. Skim 1-2 successful runs for contrast.
3. Refresh merged status: for ledger rows with pr_url from the last 14 days, run `gh pr view <url> --json state,mergedAt` and include merge rate in your report (don't rewrite the ledger).
4. Propose concrete edits, each backed by evidence from at least 2 distinct worker runs (the backpass evidence gate — cite the run_ids). 6. Triage each new issue (classify: bug / feature request / docs / question / spam-or-abuse), choose a disposition, and record every new issue with its disposition in that registry file before you finish:
   (a) INCORPORATE — small, safe, in-scope: implement it this pass as time allows (cap: at most 2 issues or roughly 30 minutes of pass time, whichever comes first; anything beyond that becomes QUEUED). Live-harness changes follow step 5's rules (small and safe only); a clear bug report or docs fix is its own justification and does not need 2 worker runs of evidence, but anything structural, provider/auth, or scheduling is FLAGGED instead. Public-repo-only fixes (README/docs/template wording) may be edited directly in the repo clone. After the step-7 publish pushes, comment on each incorporated issue with the fixing commit and close it.
   (b) QUEUED — legitimate but not this week: leave it open and note why in the registry.
   (c) FLAGGED — needs {{operator.name}}'s decision (scope calls, structural changes, security-sensitive, contested): leave it open, record it, and put it in your report.
